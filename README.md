# claude-code-music

Music generation using Claude Code.

Every piece here — the notes, the sound, the video — is generated from plain
Python. Symbolic composition to MIDI, numerical synthesis in numpy, audio-reactive
video drawn frame by frame with Pillow. **No AI audio or video models, no sample
libraries.** Every sound is arithmetic; every frame is drawn.

You describe what you want — a mood in a sentence, or the actual notes — and the
result is a finished music video. Nine pieces so far, deliberately unalike.

### A little about each

**`moody_drums_bundle`** — the original, and the template everything else grew
from. Still the only bundle without a `structure.json`.

**`optimistic_drums_bundle`** — built as a reproducibility test of the first one.
The MIDI regenerated byte-identical and the WAV with 100% identical PCM samples on
a different Python/numpy/scipy stack. The fixes that fell out of it — script-
relative paths, an ffmpeg fallback, in-script MP3, the `structure.json` handoff —
became the baseline every later bundle copies.

**`morning_forest_bundle`** — from *"happy and clear and full of hope… like walking
into a forest in the morning."* Its harmony arches **C → D → C → E → C**, each
modulation prepared by the dominant of the key it enters. Karplus-Strong arpeggio,
FM-bell lead, precomputed god-rays in the video.

**`simple_bach_tune`** — the opening figure of Bach's Prelude in C, twice a bar in
16ths, over sixteen bars that walk home through three descending-fifths chains. Not
one note outside C major. Additive harpsichord with a noise quill.

**`avenger_beginning_song`** — built from a two-handed keyboard layout supplied
note by note: left hand on power chords with no third, right hand on triads. Brass
and orchestral percussion, no kit. Also ships **4× and 8× renders** — true tempo
changes with the pitch untouched, not playback speed-ups.

**`music_box_waltz`** — an 8-bar tune supplied in `NOTE:BEATS`. It uses only
C D E F G, so with no sixth degree the melody cannot say whether it is major, minor
or modal — and the harmony got to decide. Harmonised in **D Dorian** because the
tune ends on D. The repo's first piece outside 4/4.

**`church_passacaglia`** — from a deliberately vague brief by someone who couldn't
write notes down: *"baroque style music like Bach, harpsichord, in church or
something."* Three questions with concrete options turned it into a piece. One
pipe-organ voice under four registrations built from real stop lists, and **no
percussion at all**.

**`mozart_sonata_allegro`** — *"like Bach but Mozart."* **Sonata form**, the only
form here that argues rather than repeats: its second subject is heard in E♭ major
at bar 13 and again in C minor at bar 41, same tune once bright and once dark. The
**first stereo bundle**, with a fortepiano modelling real string inharmonicity.

**`moonlight_storm`** — *"sound like Beethoven's Moonlight sonata"*, then the first
movement **into** the third, dying away at the end. A shape Beethoven never wrote:
the storm arrives and then dissolves. All 648 notes ring a full 3.4 seconds under a
held sustain pedal, and it accelerates from triplets to 32nds without changing
tempo.

## Making a new one

Point Claude Code at [`template/instructions.md`](template/instructions.md) and say
what you want — even just "create a new music video." It asks a short batch of
questions, defaults everything else, builds the bundle, verifies it, and hands you
the `.mp4`.

**Which questions depends on what you brought.**

### If you have a mood but no notes

Three questions, because nothing sensible can be guessed for them:

1. **Mood or genre, in your own words.** One sentence. "Nocturnal jazz, smoky bar,
   brushes not sticks." "Driving and mechanical, like a train at night."
2. **Key and mode** — or "you pick." Mode matters more than key: Dorian, Lydian
   and Phrygian on the same root are three different pieces.
3. **Does the harmony go anywhere?** Just loop, one key change, an arch, a gradual
   darkening, a build and release, a false ending?

You do not need any theory for this. `church_passacaglia` came from one vague
sentence and three multiple-choice answers.

### If you have the notes

Write them as `NOTE:BEATS`, one bar per line, and make each line add up to a bar:

```
E4:1.5 F4:0.5 E4:1        <- 3 beats: a bar of 3/4
G4:2 G4:1                 <- 3
```

`E4` on its own means one beat; `R:1` is a rest; `[E4 G4 B4]:2` is a chord. That
last rule — every line sums to a bar — catches your own typos before anyone else
sees them, and it settles the meter without discussion. This is how
`music_box_waltz` was written.

If you give pitches but no rhythm, the questions become rhythm, form and
orchestration instead — that's how `avenger_beginning_song` was built, from a
two-handed keyboard layout with no durations at all.

### Things worth asking for

A specific instrument · a reference to an existing bundle ("like the moody one but
faster") · a meter · no drums · stereo · a section count · where a key change lands
· 4× and 8× speed variants · the folder name.

**What it cannot do:** vocals, lyrics, real recorded instruments, or reproducing an
existing song. Every sound is synthesized from arithmetic, so there is no voice and
no sample library. "In the style of" is fine; "that exact song" is not.

### What else is in `instructions.md`

The invariant framework contract, a library indexing all 21 pitched voices and 12
drum voices across the bundles with the six synthesis techniques they are built
from, patterns for growing short material into a full piece, how to render speed
variants without wrecking the pitch, the build procedure, and the verification
every bundle has to pass. It grows with each piece — **every bundle so far has
taught it at least one thing**, and adding a piece without adding what it taught is
half the job.

## Running a bundle

```bash
pip install numpy scipy pillow midiutil imageio-ffmpeg

cd template/<bundle>/scripts        # e.g. template/moonlight_storm/scripts
python3 01_make_music.py            # -> ../assets/{mid,wav,mp3}, ../structure.json
python3 02_make_video.py            # -> ../assets/<name>_visualizer.mp4
```

Use the folder name exactly as it appears above — three end in `_bundle` and six do
not, because those were the names asked for.

No system ffmpeg required; the scripts fall back to the static binary bundled with
`imageio-ffmpeg`. Expect a few seconds for the audio and roughly 1.3 s of render
per second of music for the video.

## Reproducibility

The MIDI is deterministic. The audio is deterministic down to the sample — but
check the **PCM data**, not the WAV file:

```python
import hashlib
from scipy.io import wavfile
sr, a = wavfile.read("assets/<name>.wav")
print(hashlib.md5(a.tobytes()).hexdigest())
```

WAV file-level MD5s differ across scipy versions over optional RIFF chunks while
the samples stay bit-identical, so the file hashes recorded in each bundle README
are reference only. MP3 and MP4 bytes vary with the ffmpeg build; the audible and
visible content does not.
